## Automated config gate

`npm run dist:clinical` / `dist:clinical:pub` now run `npm run check:config` first (`scripts/check-build-config.ps1`) — it reads the literal defaults in `config.py` and **fails the build** unless `WEB_API_URL` or both Supabase creds are set, so a no-licence-backend build can't be produced. (The packaged backend also logs a loud stderr error in this state, but does not crash — clinical data must stay reachable.) Checklist item #2 is therefore enforced, not just documented.

## License server note

Two production paths exist — set exactly one before building:

- **`WEB_API_URL` (recommended):** desktop calls the Next.js web API at `privatespace.co`, which proxies to Supabase using the server-side service-role key — no Supabase credentials needed in the binary.
- **`SUPABASE_URL` + `SUPABASE_ANON_KEY` (fallback):** desktop calls Supabase directly using the Publishable (anon) key — safe to hardcode, but puts credentials in the installer.

In local dev, leave both blank — any well-formatted key is accepted with no network calls.

## AI model note (dev machine)

`private_storage/models/` currently holds a real downloaded copy of the E2B QAT model (no symlinks as of 2026-06-10). Historically this dir used `mklink` symlinks to Ollama blobs to avoid duplicating large files — if symlinks are ever recreated, their names must match the `"filename"` values in `AVAILABLE_MODELS` exactly or the status check will always report "not set up". Before building the installer, remove any model files/symlinks — models are not bundled in the installer and customers download them via Settings on first use.
